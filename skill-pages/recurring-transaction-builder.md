# Recurring Transaction Builder

> Design a recurring schedule, then audit whether it ran.

**Skill:** `recurring-transaction-builder`  ·  **Area:** Payroll, entry review, forecasting and fixed assets  ·  **Automated with Mosofin connected:** 64%  ·  **Read-only**

## What it does

Helps you design, schedule, or validate recurring transactions against a connected Mosofin workspace — recurring journal entries, recurring bills, recurring invoices, or subscription billing schedules.

## When to use it

Use it when you ask for any of these, or something like them.

Typical requests:

- "set up a recurring JE for"
- "create a recurring bill schedule"
- "generate the next 12 months of recurring entries"
- "automate this monthly entry"
- "subscription invoice template"
- "did our recurring entry run"
- "what should we be automating"

Not for:

- One-off entries — use [journal-entry-builder](journal-entry-builder.md).
- Prepaid amortization specifically — use [prepaid-amortization-schedule](prepaid-amortization-schedule.md). Produces a validated recurring schedule with every future occurrence computed, checked against the live chart of accounts, and ready for a human to load. Mosofin does not create templates, does not post, and does not schedule anything.

## What it asks you first

Before it reads anything, it asks which company and which period the work is for, whether to use your Mosofin connection or files you supply, and for the facts the books cannot hold, such as a policy, a threshold or a date. It reads the answers back and waits for your yes.

## With or without Mosofin

With a Mosofin workspace connected, and only after you agree, the skill reads the figures from your own books. Without a connection it runs the same analysis on files you upload, and the output says which figures came from where.

If you upload the data yourself:

| Upload | Needed? | Format |
|---|---|---|
| Transaction type | Required | Recurring JE / Bill / Invoice / Subscription |
| Counterparty | Required for AP/AR | Vendor or customer name |
| Amount and currency | Required | Per occurrence |
| Start date | Required | First occurrence |
| End date or number of occurrences | Required | One of the two |
| Cadence | Required | Daily / Weekly / Bi-weekly / Semi-monthly / Monthly / Quarterly / Semi-annually / Annually / Custom |
| Day-of-period rule | Required | First day / Last day / Specific day / Last business day / N business days into period |
| GL account(s) and posting template | Required for JEs | From your COA |
| Tax code | Required if tax applies | Per your jurisdiction and tax setup |
| Description / memo template | Recommended | Text with variables `{month}`, `{year}` |
| Escalation rule | Optional | Fixed / Annual % / CPI-linked / Step-up at date |
| Stop / pause conditions | Optional | Termination clauses |

Every uploaded file is checked before any work starts: that it is the right kind of document, for the right company and period, and usable.

## What you get

Every entry and output is a proposal for a person to act on, and nothing is posted, sent or paid.

- Schedule Summary
- Occurrence Schedule
- Per-Occurrence JE / Bill / Invoice Detail
- Reversal Schedule
- Validation and Discovery
- Coverage and Provenance

Every run ends with a coverage sheet: what was checked, what was estimated, and what could not be done and why.

## What it never does

- **Asks before using Mosofin.** A connected account is not permission to read it.
- **Never writes, updates or deletes anything, in any system.** Every entry, message or change it suggests is a proposal for a person to approve.
- **Says what it could not check.** Anything it could not verify is listed, with what you would need to supply.
