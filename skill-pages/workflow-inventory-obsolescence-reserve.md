# Inventory obsolescence reserve (workflow)

> Checks Mosofin data on a schedule or on demand and proposes reserve adjustment entry.

**Workflow:** `inventory-obsolescence-reserve`  ·  **Runs in:** n8n  ·  **Read-only**

## What it does

Ages each item by days since its last sale, applies a tiered reserve percentage, and compares the required reserve with the one on the books. Proposes the adjusting entry.

- File-driven: an inventory listing with quantity, unit cost and last-sale date.
- Days since last sale picks the highest `aging_tiers` tier reached; no sale date uses `never_sold_pct`.
- Required reserve minus `existing_reserve` is the proposed adjustment (either direction).

## When it runs

Runs quarterly on its own, and whenever something sends it a request.

It works from the files you send it and needs no Mosofin read.

## What you send it

| File | What it must be | Required |
|---|---|---|
| `items` | inventory listing with last-sale dates | yes |

Every file is checked on its content before any work: right kind of document, right company, usable. A rejected required file stops the run; a rejected optional file is skipped and named in the result.

## What you can change

Every setting sits in one place, and any of them can be overridden for a single run.

| Setting | Meaning |
|---|---|
| `company` | Company the run is for; a file naming another company is rejected |
| `currency` | Reporting currency, echoed in the envelope |
| `datasource` | Mosofin datasource name (e.g. quickbooks, xero) |
| `as_at` | As-at date (YYYY-MM-DD); empty = run date |
| `aging_tiers` | Days since last sale -> reserve percent; the highest tier reached applies |
| `never_sold_pct` | Reserve percent for items with no sale date |
| `existing_reserve` | Reserve balance on the books now |
| `reserve_account` | Contra-inventory account |
| `expense_account` | P&L account for the adjustment |

## What comes back

One result for the next step to use: an email connector, a chat post, a dashboard or another tool. It holds the findings, the totals, what could not be done and why, and the proposed actions, each waiting for a person's approval.

**It proposes:** Reserve adjustment entry.

## What it never does

- **Never posts, sends, pays or changes anything.** The only outbound calls are reads through the Mosofin gateway.
- **Never acts on its own proposals.** An email draft, a journal entry, a hold or a payment is handed to a person to approve first.
- **Never trusts a file by its name.** Each file is checked on its content before it is used.
