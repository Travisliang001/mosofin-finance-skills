# Invoice ingestion and coding (workflow)

> Checks Mosofin data on a schedule or on demand and proposes bill drafts with GL coding, new vendors.

**Workflow:** `invoice-ingestion`  ·  **Runs in:** n8n  ·  **Read-only**

## What it does

Turns supplier invoice lines into bill drafts: matches the vendor to the vendor list, codes each line to a GL account by keyword rules, and flags unknown vendors and lines no rule covers. Proposes the bills; enters nothing.

- Input is invoice lines as CSV/rows. Scanned PDFs or images need an extraction step first (for example an LLM node before the webhook) that produces these columns.
- Groups lines into invoices by vendor + invoice number.
- Each line coded by the first matching `coding_rules` keyword; unmatched lines go to `default_expense_account` and are flagged.

## When it runs

Runs when something sends it a request, for example when a file arrives.

With a Mosofin data source set, it reads the vendor list through the Mosofin gateway. Where a file you send covers the same data, the Mosofin figures are used first and the file is the fallback.

## What you send it

| File | What it must be | Required |
|---|---|---|
| `invoice_lines` | supplier invoice lines | yes |
| `vendors` | vendor list | no |

Every file is checked on its content before any work: right kind of document, right company, usable. A rejected required file stops the run; a rejected optional file is skipped and named in the result.

## What you can change

Every setting sits in one place, and any of them can be overridden for a single run.

| Setting | Meaning |
|---|---|
| `company` | Company the run is for; a file naming another company is rejected |
| `currency` | Reporting currency, echoed in the envelope |
| `datasource` | Mosofin datasource name (e.g. quickbooks, xero) |
| `default_expense_account` | Account used when no rule matches; such lines are flagged |
| `coding_rules` | Ordered list of { keyword (regex), account }; first match codes the line |

## What comes back

One result for the next step to use: an email connector, a chat post, a dashboard or another tool. It holds the findings, the totals, what could not be done and why, and the proposed actions, each waiting for a person's approval.

**It proposes:** Bill drafts with GL coding, new vendors.

## What it never does

- **Never posts, sends, pays or changes anything.** The only outbound calls are reads through the Mosofin gateway.
- **Never acts on its own proposals.** An email draft, a journal entry, a hold or a payment is handed to a person to approve first.
- **Never trusts a file by its name.** Each file is checked on its content before it is used.
