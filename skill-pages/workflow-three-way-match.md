# Three-way match (workflow)

> Checks your books on demand and proposes holds on bills with exceptions.

**Workflow:** `three-way-match`  ·  **Runs in:** n8n  ·  **Read-only**

## What it does

Checks each bill line against its purchase order and goods-received record. Price and quantity variances over tolerance, bills with no PO line, and billing beyond what was received come back as exceptions with a proposed hold.

It runs inside n8n, an automation tool you host, and reads your books only through your Mosofin connection, the same read-only connection the skills use.

## When it runs

It runs on demand: whenever another step sends it a request, for example when a file arrives.

With a Mosofin data source set, it reads supplier bills through your Mosofin connection. Where a file you send covers the same data, the Mosofin figures are used first and the file is the fallback.

## What you send it

| File | What it must be | Required |
|---|---|---|
| `purchase_orders` | purchase order lines | yes |
| `receipts` | goods received lines | no |
| `bills` | bill lines | no |

Every file is checked on its content before any work: right kind of document, right company, usable. A rejected required file stops the run; a rejected optional file is skipped and named in the result.

## What you can change

Every setting sits in one place in the workflow, and any of them can be overridden for a single run by the request that starts it.

| Setting | Meaning |
|---|---|
| `company` | Company the run is for; a file naming another company is rejected |
| `currency` | Reporting currency, shown in the result |
| `datasource` | Mosofin datasource name (e.g. quickbooks, xero) |
| `price_tolerance_pct` | Allowed unit-price difference vs the PO, in percent |
| `qty_tolerance` | Units a bill may exceed the received (or ordered) quantity by |

## What comes back

One structured result (JSON), for the next step in your automation to use: an email tool, a chat post, a dashboard or another workflow. It holds the findings, the totals, what could not be done and why, and the proposed actions, each waiting for a person's approval.

**It proposes:** Holds on bills with exceptions.

## What it never does

- **Never posts, sends, pays or changes anything.** The only outbound calls are reads through your Mosofin connection.
- **Never acts on its own proposals.** An email draft, a journal entry, a hold or a payment is handed to a person to approve first.
- **Never takes a file at face value.** Each file is checked on its content, not its name, before it is used.
