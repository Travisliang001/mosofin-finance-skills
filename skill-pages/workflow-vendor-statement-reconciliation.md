# Vendor statement reconciliation (workflow)

> Checks Mosofin data on a schedule or on demand and proposes queries to the vendor.

**Workflow:** [vendor-statement-reconciliation](vendor-statement-reconciliation.md)  ·  **Runs in:** n8n  ·  **Read-only**

## What it does

Reconciles a supplier's statement to the bills and payments in the books for that vendor: items on the statement but not in the books, items in the books not on the statement, and amount differences on the same reference.

- The statement is required; the vendor's bills come from Mosofin (A/P ledger file as fallback).
- Statement lines matched to book records by normalised reference.
- Lists statement-only items, book-only items and same-reference amount differences, then proves those explain the total difference.

## When it runs

Runs when something sends it a request, for example when a file arrives.

With a Mosofin data source set, it reads supplier bills through the Mosofin gateway. Where a file you send covers the same data, the Mosofin figures are used first and the file is the fallback.

## What you send it

| File | What it must be | Required |
|---|---|---|
| `statement` | supplier statement | yes |
| `ap_ledger` | A/P ledger for the vendor | no |

Every file is checked on its content before any work: right kind of document, right company, usable. A rejected required file stops the run; a rejected optional file is skipped and named in the result.

## What you can change

Every setting sits in one place, and any of them can be overridden for a single run.

| Setting | Meaning |
|---|---|
| `company` | Company the run is for; a file naming another company is rejected |
| `currency` | Reporting currency, echoed in the envelope |
| `datasource` | Mosofin datasource name (e.g. quickbooks, xero) |
| `vendor` | Vendor whose statement this is (as named in the books) |
| `as_at` | As-at date (YYYY-MM-DD); empty = run date |
| `amount_tolerance` | Differences at or below this are ignored |

## What comes back

One result for the next step to use: an email connector, a chat post, a dashboard or another tool. It holds the findings, the totals, what could not be done and why, and the proposed actions, each waiting for a person's approval.

**It proposes:** Queries to the vendor.

## What it never does

- **Never posts, sends, pays or changes anything.** The only outbound calls are reads through the Mosofin gateway.
- **Never acts on its own proposals.** An email draft, a journal entry, a hold or a payment is handed to a person to approve first.
- **Never trusts a file by its name.** Each file is checked on its content before it is used.
