# Fixed asset rollforward (workflow)

> Checks Mosofin data on a schedule or on demand and proposes missing depreciation entries.

**Workflow:** `fixed-asset-rollforward`  ·  **Runs in:** n8n  ·  **Read-only**

## What it does

Rolls the fixed asset register forward for the period (opening cost, additions, disposals, closing) and checks straight-line depreciation posted per asset against what the register says it should be. Missing depreciation comes back as a proposed entry.

- The register is required (asset id, cost, in-service date, life in months; salvage and disposal date optional).
- Cost rollforward: opening + additions - disposals = closing for the period.
- Expected depreciation: straight line, full month from the in-service month, stops at end of life or the disposal month.
- Posted depreciation is attributed to an asset when its memo contains the asset id; differences over `materiality` are flagged.

## When it runs

Runs monthly on its own, and whenever something sends it a request.

With a Mosofin data source set, it reads the general ledger through the Mosofin gateway. Where a file you send covers the same data, the Mosofin figures are used first and the file is the fallback.

## What you send it

| File | What it must be | Required |
|---|---|---|
| `register` | fixed asset register | yes |
| `depreciation_gl` | depreciation postings | no |

Every file is checked on its content before any work: right kind of document, right company, usable. A rejected required file stops the run; a rejected optional file is skipped and named in the result.

## What you can change

Every setting sits in one place, and any of them can be overridden for a single run.

| Setting | Meaning |
|---|---|
| `company` | Company the run is for; a file naming another company is rejected |
| `currency` | Reporting currency, echoed in the envelope |
| `datasource` | Mosofin datasource name (e.g. quickbooks, xero) |
| `period_start` | First day of the period (YYYY-MM-DD) |
| `period_end` | Last day of the period (YYYY-MM-DD) |
| `depreciation_account` | Expense account depreciation is posted to (read from the GL) |
| `accumulated_account` | Credit side of proposed depreciation entries |
| `materiality` | Differences below this per asset are ignored |

## What comes back

One result for the next step to use: an email connector, a chat post, a dashboard or another tool. It holds the findings, the totals, what could not be done and why, and the proposed actions, each waiting for a person's approval.

**It proposes:** Missing depreciation entries.

## What it never does

- **Never posts, sends, pays or changes anything.** The only outbound calls are reads through the Mosofin gateway.
- **Never acts on its own proposals.** An email draft, a journal entry, a hold or a payment is handed to a person to approve first.
- **Never trusts a file by its name.** Each file is checked on its content before it is used.
