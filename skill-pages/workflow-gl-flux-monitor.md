# GL flux monitor (workflow)

> Checks Mosofin data on a schedule or on demand and proposes explanation requests per owner.

**Workflow:** `gl-flux-monitor`  ·  **Runs in:** n8n  ·  **Read-only**

## What it does

Compares each P&L account this period with the prior period and flags movements over both a percentage and an absolute threshold, plus accounts that went to zero or appeared from nothing. Asks the account owner for an explanation.

- Reads the P&L by account for the period and the comparison period (files as fallback).
- Flags an account when the change passes BOTH `flux_pct` and `flux_abs`; also `went_to_zero` and `new_activity` above `flux_abs`.
- Groups flagged accounts by owner into one explanation request each.

## When it runs

Runs monthly on its own, and whenever something sends it a request.

With a Mosofin data source set, it reads the profit and loss through the Mosofin gateway. Where a file you send covers the same data, the Mosofin figures are used first and the file is the fallback.

## What you send it

| File | What it must be | Required |
|---|---|---|
| `current` | P&L by account (current period) | no |
| `prior` | P&L by account (prior period) | no |

Every file is checked on its content before any work: right kind of document, right company, usable. A rejected required file stops the run; a rejected optional file is skipped and named in the result.

## What you can change

Every setting sits in one place, and any of them can be overridden for a single run.

| Setting | Meaning |
|---|---|
| `company` | Company the run is for; a file naming another company is rejected |
| `currency` | Reporting currency, echoed in the envelope |
| `datasource` | Mosofin datasource name (e.g. quickbooks, xero) |
| `period_start` | First day of the period (YYYY-MM-DD) |
| `period_end` | Last day of the period (YYYY-MM-DD) |
| `prior_start` | First day of the comparison period |
| `prior_end` | Last day of the comparison period |
| `flux_pct` | Percent change that trips a flag (both thresholds must trip) |
| `flux_abs` | Absolute change that trips a flag |
| `account_owners` | { "account": "owner" } for explanation requests |
| `default_owner` | Owner when an account has none |

## What comes back

One result for the next step to use: an email connector, a chat post, a dashboard or another tool. It holds the findings, the totals, what could not be done and why, and the proposed actions, each waiting for a person's approval.

**It proposes:** Explanation requests per owner.

## What it never does

- **Never posts, sends, pays or changes anything.** The only outbound calls are reads through the Mosofin gateway.
- **Never acts on its own proposals.** An email draft, a journal entry, a hold or a payment is handed to a person to approve first.
- **Never trusts a file by its name.** Each file is checked on its content before it is used.
