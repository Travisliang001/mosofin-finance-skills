## Output Quality Standards

All of the original standards, plus the Mosofin ones.

- **Plan defines objectives, scope, criteria, and risk-based focus**
- **Audit program links every procedure to an objective; full coverage**
- **Workpapers let a reviewer re-perform and reach the same conclusion; evidence-backed and referenced**
- **Findings use condition / criteria / cause / consequence / recommendation with genuine root cause**
- **Findings risk-rated consistently** (likelihood × impact)
- **Management responses obtained; disagreements documented objectively**
- **Report is structured, objective, constructive, with an overall conclusion**
- **Follow-up tracks remediation and re-tests completion**
- **Independence / objectivity and scope limitations flagged**
- **File naming consistent**

**Mosofin additions:**

- The workspace was confirmed **by name** and the user said yes before any data was read
- Every in-scope company file is named by `display_name`; **every excluded entity and every `disabled` tool
  is recorded as a scope limitation with its effect on the conclusion**
- The capability map was discovered **this run** via Gate 2 — never recalled from a previous conversation
  or from this file
- **Every procedure in the program carries its type, its verdict, and its population approach**
- **Full populations were tested wherever readable**, with the count stated; **where a sample was used, the
  method, size and basis are stated** and the reason a full test was not possible is given
- **Every objective has at least one procedure**, and objectives concerning effectiveness, efficiency or
  authorisation **have `[manual]` fieldwork assigned to a named performer**
- **Completeness is not claimed from ledger data alone**; where it is in scope, the external reference point
  is named
- **Every `[auto]` workpaper records the tool, the parameters, the entity and the as-at date**, so the
  procedure is genuinely re-performable
- **Conditions are evidenced and consequences quantified** where the data allows; **causes are `[manual]`
  and were obtained by asking**, not inferred from data
- **An absence of exceptions is not reported as a control operating effectively**
- **Risk ratings cite the quantified exposure** where one exists
- **Repeat findings are identified by re-running the stored test**, not from recollection
- **Follow-up re-tests repeat the original test definition**
- In a multi-entity run, **exception rates are reported per entity as well as in total**, populations are
  not aggregated across entities, and an entity where a test could not run is a scope limitation for the
  group conclusion
- Every task carries its verdict (`[auto]` / `[gated]` / `[manual]`), the tool or external source used, and
  its as-at date, in the coverage sheet
- `mock` status is reported wherever it applies, and **no audit conclusion rests on mock data**
- Every figure traces to a tool result in this conversation or to labelled user-supplied evidence; the
  answer ends with a single **Data sources** line
- Every jargon term carries a plain-language gloss at first mention, with the professional term kept
  alongside
- No internal numeric ids and no raw `data_source_id` values appear in anything the user sees
- **No findings, exceptions, populations, management responses or individuals' names are persisted** into a
  skill bundle — **the program and the test definitions are stored; the results never are**; every persisted
  preference states the datasource and `display_name` it covers
- Nothing was written back to any system — the audit changed no record it examined
